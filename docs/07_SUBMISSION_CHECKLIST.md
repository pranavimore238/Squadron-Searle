# Submission checklist

## Must confirm against Moodle / instructor

- [ ] Is the required deliverable software, report, presentation, or a combination?
- [ ] Is the proposed website an acceptable interpretation of the topic?
- [ ] Is a particular language/framework mandatory?
- [ ] Is a report length or template specified?
- [ ] Is a citation style specified?
- [ ] Is a live deployment URL required?
- [ ] Are all team members required to submit individually or is one group submission enough?
- [ ] Are there rules for use/disclosure of AI tools?

## Project quality

- [ ] Replace all placeholders that are required.
- [ ] Verify institution name, course, supervisor, student/team details.
- [ ] Read the primary source and check claims.
- [ ] Confirm all citations and URLs.
- [ ] Run and record tests actually executed.
- [ ] Test the application locally.
- [ ] Review responsive layout and keyboard operation.
- [ ] Ensure README matches the actual app.
- [ ] Remove secrets and unnecessary personal data.
- [ ] Confirm the GitHub repository is accessible to the instructor if a repository link is required.
- [ ] Verify a live URL before sharing it, if deployment is required.
- [ ] Keep a copy of the exact submitted ZIP / commit.

## Institutional note

The formal BTU rubric and required report format were not provided. This checklist is a general project checklist, not an official Brandenburg University of Technology submission standard.
